## 旋转路径核查（只读）

- 三种「旋转」要分开：平面内歪头靠 `Models.recognize` 的 5 点相似变换天然
  吸收；yaw 侧脸是第 5 章的事；**整帧 90/180/270 度**才需要 OrientAutoSwitch。
- GUI 的 `OrientAutoSwitch` 默认 False、没有 CLI 开关（只能 `--params`），且
  三个坑：跨帧状态在 workers>1 竞态（vm 是单实例共享）、EMA 非 90 倍数角度
  配 `expand=True` 正逆两次旋转让画布膨胀（编码器写死输入宽高）、正旋
  BILINEAR / 逆旋 NEAREST 插值不对称。
- 现有实现是「整帧转正 → 旋转域里检测/识别/换脸 → 整帧逆旋」，kps 不需要
  逆映射；README 5.6 说的「旋转重试需要 kps 逆映射」是被放弃的另一种方案。

## 整帧朝向兜底已实现（用户要求「自动打开」，纯写代码、无真机验证）

- **没有直接把 `OrientAutoSwitchState` 翻成 True**——那会让正常视频也被
  EMA 带着旋转、触发尺寸漂移和竞态。改成一套**逐帧无状态**的新机制：
  - 新增 `faceswapper/orientation.py`（stdlib-only）：`PROBE_ANGLES=(90,180,270)`、
    `should_probe(detected, enabled, already_rotated)`、`choose_angle(counts)`
    （平手/全 0 取 0，只认候选角度）。
  - `VideoManager._swap_video_inner`：第一遍检测**已有脸就结束**（正常帧零
    额外推理、逐像素不变）；只有 0 检出帧才试 90/180/270，取检出最多的角度
    转正重检，后续识别/换脸在旋转域跑完，末尾复用既有逆旋分支转回。
  - 默认开启，回滚开关 `--no-auto-orient`（add_common，swap/video/inspect 共有）。
    走 `SwapOptions.no_auto_orient` → `_SwapperBase` 注入
    `vm.auto_orient_fallback`，**不碰 parameter dict / saved_parameters.json**。
- 三个坑的规避方式（写进 README 5.7）：只用 90 倍数 → `expand=True` 可逆、
  帧尺寸不变、NEAREST/BILINEAR 在 90 倍数下都是纯索引重排；无跨帧状态 →
  `--workers 2` 安全；不做亚 90 度微调 → 歪头交给 5 点相似变换。
  GUI `OrientAutoSwitch`/`OrientSwitch` 显式开启时兜底让位，不叠加旋转。
