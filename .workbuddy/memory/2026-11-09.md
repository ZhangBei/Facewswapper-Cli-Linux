## 用户澄清后修正：痛点是大角度 roll 漏检，不是侧脸

- **收回上一节的「roll/yaw 混淆」质疑**：用户明确方案不是针对侧脸检测，而是脸在画面内大角度 roll 后 detector 漏检。S3 把画布转正再检测是对症的标准解法，出发点没问题。相应地上一节把收益压到 0.3% 也偏低（当时假设 pr=30%），按 pr≈1 重算后文档的 +1.16pp 量级是合理的。
- **核心判据收敛到一个数 `theta_tol`**（detector 对 roll 的容忍半宽）：4 向 = 轴 0/90/180/270。若 theta_tol >= 45°，4 向覆盖区间首尾相接，8/16 向增益**恒为 0**，S3 白做；theta_tol < 45° 才出现盲区。故文档 S0「p<2% 则不必做」的几何本质就是测 theta_tol。
- **量化（新增 `tools/probe_roll_recall.py`，stdlib-only，已实跑）**：覆盖率模型 = 至少有一个 probe 轴使环形距离 <= 该轴有效容忍半宽；非 90 倍数轴（BILINEAR 插值 + expand 画布膨胀）扣 delta（默认 5°）。
  - delta=5 / p0=5% / pr=1：theta_tol=30° → 4向 66.7%、8向 100%、漏检帧救回 100%、整体 +1.667 pp；theta_tol=40° → +0.556 pp；theta_tol>=45° → 0 pp。
  - delta 从 0 扫到 10，结论稳健：theta_tol>=28~30° 时 8 向已饱和 100%，**16 向几乎零增量**（只在 theta_tol<=24° 或 delta>=10 时才有额外收益）→ 建议直接砍掉 16 向，只做 8 向。
  - 整体收益公式 = p0 × (c8 - c4) × 100 pp；p0 才是量级决定因素（p0=1% → 0.33pp，5% → 1.67pp，10% → 3.33pp @ theta_tol=30°）。文档 +1.16pp 对应 p0≈3.5%。
- **触发面结论要限定**：若素材是单人特写，roll 漏检 = 0 检出帧，现有 `should_probe` 直接触发，上一节最担心的错配**不成立**；只有帧里还有别的脸被检出（detected>0）时 S3 才不触发、才需要 S5 类改动。S4 仍低价值（解决帧内多朝向，与单点 roll 漏检不同）；路线 B 架构改动仍值得单独做。
